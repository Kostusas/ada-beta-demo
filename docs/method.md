# Scientific provenance and measurement

**Input.** The 404 × 404 probability map is an exact copy of `Contact_files/condensin_hic_contact_r_5.txt` at commit `3fb7dea343f8426140f38442c47eba000e80b9f2`. Its SHA-256 is `81f921d346eef394910f168ce3e551fc017275044d2755dccf13feb7450729bd`. The map gives the fraction of simulation snapshots in which two selected beads are within the contact radius. The 4.04 Mb circular chromosome has one selected bead every 10 kb. Figure axes use offsets from the first bead. [Original input](https://github.com/PLSysGitHub/chromosomal_multi_contact_data/blob/3fb7dea343f8426140f38442c47eba000e80b9f2/Contact_files/condensin_hic_contact_r_5.txt)

**Prediction.** For symmetric pair probabilities a, b and c, the model evaluates `min(1, a*b + b*c + c*a - 2*a*b*c)`. Repeated loci and circular nearest neighbours have zero output. The code preserves the authors’ indexing and arithmetic order. Each Julia thread owns distinct output planes along the third axis. A single full-size tensor is live during prediction. The bundled heatmap uses the same radius, 10 kb resolution, bait index and triplet color limits as the original example. Measured three-point data are a separate scientific observable. [Example script](https://github.com/PLSysGitHub/chromosomal_multi_contact_data/blob/3fb7dea343f8426140f38442c47eba000e80b9f2/Example_Condensin.jl) · [Authors’ bait-200 image](https://github.com/PLSysGitHub/chromosomal_multi_contact_data/blob/3fb7dea343f8426140f38442c47eba000e80b9f2/Output/Condensin_example/Contact_radius_5/loop_extr_triplets_bait_200.png)

**Reference implementation.** The functions `loop_extr` and `d_periodic` in `src/upstream/loop_extr.jl` are verbatim excerpts. The serial and threaded paths run in separate processes; full-volume validation hashes a byte view of the array outside the timed region. The high-memory path checks a sparse grid to avoid a second dense cube. The notebook independently evaluates one plane using NumPy, compares it to the saved Julia values on load and reconstructs other bait positions on demand. [Original functions](https://github.com/PLSysGitHub/chromosomal_multi_contact_data/blob/3fb7dea343f8426140f38442c47eba000e80b9f2/ContactTripletPredictions.jl) · [Upstream MIT notice](../src/upstream/LICENSE)

**Timing.** Each thread count starts a fresh process. Small-array calls compile both predictor methods before the measured trials. Input parsing, explicit pre-trial garbage collection, SHA-256 and file writes are outside the timer. Allocation, page faults and the kernel calculation are inside. Speedup divides the threaded one-thread median by the threaded multi-core median. Parallel efficiency divides that ratio by the number of threads. The original serial result is also timed. Average busy cores are process CPU seconds divided by wall seconds. CPU utilization as a percentage of requested worker capacity is 100 times that value divided by the thread count. Slurm reserves the full sweep allocation throughout.

**Memory.** Julia’s `Sys.maxrss()` gives process-lifetime peak resident bytes up to the end of that trial, including runtime and input loading. Later trials in the same process inherit its previous high-water mark. Slurm’s requested memory and sampled MaxRSS are separate measurements. OS, processor, runtime version and allocation metadata accompany the raw samples.

**Coordinate check.** The local extractor read all 3,060 snapshots at stride 10 using only a pair-contact matrix. The maximum difference from the supplied published map was one observation in 3,060. A separate one-frame check compared sampled 2, 4 and 10 kb rows against direct Euclidean distances. Full fine-resolution runs belong on ADA. [Original extraction](https://github.com/PLSysGitHub/chromosomal_multi_contact_data/blob/3fb7dea343f8426140f38442c47eba000e80b9f2/Extract_triplets/Extract_triplets_Brandao_et_al.jl)
