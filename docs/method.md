# Scientific provenance and measurement

**Input.** The 404 × 404 probability map is an exact copy of `Contact_files/condensin_hic_contact_r_5.txt` at commit `3fb7dea343f8426140f38442c47eba000e80b9f2`. Its SHA-256 is `81f921d346eef394910f168ce3e551fc017275044d2755dccf13feb7450729bd`. The map gives the fraction of simulation snapshots in which two selected beads are within the contact radius. The 4.04 Mb circular chromosome has one selected bead every 10 kb. Figure axes use offsets from the first bead. [Original input](https://github.com/PLSysGitHub/chromosomal_multi_contact_data/blob/3fb7dea343f8426140f38442c47eba000e80b9f2/Contact_files/condensin_hic_contact_r_5.txt)

**Prediction.** For symmetric pair probabilities a, b and c, the model evaluates `min(1, a*b + b*c + c*a - 2*a*b*c)`. Repeated loci and circular nearest neighbours have zero output. The code preserves the authors’ indexing and arithmetic order. Each Julia thread owns distinct output planes along the third axis. A single full-size tensor is live during prediction. The bundled heatmap uses the same radius, 10 kb resolution, bait index and triplet color limits as the original example. Measured three-point data are a separate scientific observable. [Example script](https://github.com/PLSysGitHub/chromosomal_multi_contact_data/blob/3fb7dea343f8426140f38442c47eba000e80b9f2/Example_Condensin.jl) · [Authors’ bait-200 image](https://github.com/PLSysGitHub/chromosomal_multi_contact_data/blob/3fb7dea343f8426140f38442c47eba000e80b9f2/Output/Condensin_example/Contact_radius_5/loop_extr_triplets_bait_200.png)

**Live benchmark.** One Julia worker fills a preallocated Float64 tensor. Each compute thread owns distinct bait planes. A warm-up at the selected resolution compiles the method and touches the output pages. The worker then repeats complete predictions until their cumulative kernel time reaches the selected window. Speedup divides the median pass time at the lowest measured thread count by the median at the target thread count for the same resolution. The table names that baseline. Relative efficiency divides speedup by the ratio of target to baseline thread counts. The benchmark excludes loading, warm-up, validation and file writes from pass times. Those phases are visible in the process monitor.

**Correctness.** At 101 loci the live worker checks every entry against the original serial implementation outside the timed window. At 404 it also checks the saved bait-200 plane. A SHA-256 digest of the entire cube verifies agreement between thread counts at each standard level. Fine-resolution runs check an eligible grid against serial. The command-line reproduction path `python3 demo.py scale` also runs the original serial version at full published resolution. Its timings include output allocation. [Original functions](https://github.com/PLSysGitHub/chromosomal_multi_contact_data/blob/3fb7dea343f8426140f38442c47eba000e80b9f2/ContactTripletPredictions.jl)

**What the meters measure.** The Python kernel samples its Julia child roughly every 450 ms. Process CPU seconds divided by sample wall time gives busy CPU equivalents. Dividing that by the session CPU count gives session utilization. The CPU count uses process affinity where available and caps it at the CPU request exported by the session. OS thread meters use changes in per-thread user and system time. A reading of 100% corresponds to one logical CPU over that interval. Julia also starts runtime and garbage collector threads. Thread IDs identify OS threads. On Linux the adjacent CPU number is the logical processor where the thread last ran. The scheduler can move a thread between processors. [Linux proc file format](https://man7.org/linux/man-pages/man5/proc_pid_stat.5.html) The results table measures average busy CPUs across the full timed window using the worker’s process clock.

**Memory and persistence.** The monitor reports the worker’s current resident set. The results table uses Julia’s process-lifetime peak RSS. The plan estimates the dense output as eight bytes per entry. Each unique session directory contains `session.json` with hardware, timings, passes and checks, plus `telemetry.jsonl` with timestamped samples and `bait-N.f64` with a single Float64 matrix per resolution in Julia column-major order. Complete configurations survive cancellation. Reopening the notebook discovers saved results and replay reads those recorded samples.

**Coordinate check.** The local extractor read all 3,060 snapshots at stride 10 using only a pair-contact matrix. The maximum difference from the supplied published map was one observation in 3,060. A separate one-frame check compared sampled 2, 4 and 10 kb rows against direct Euclidean distances. Full fine-resolution runs belong on ADA.
